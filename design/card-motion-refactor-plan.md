# 卡牌区域动效系统重构计划

状态：批次 0、1、2、3a、3b、3c 已交付；批次 4 的代码与文档已更新，但完整回归和桌面目视验收尚未通过。见 [批次 4 报告](card-motion-refactor-batch4-report.md)。本文是分阶段实施与验收清单；完成迁移后，`ui/ui-guide.md` 仍是 UI 行为的正式规范，不在本文长期维护第二套规范。

## 目标和边界

引擎仍原地修改一个 `GameState`，决定卡牌真实去向、顺序、合法操作和决策；Vue 不复制规则。UI 可以在动画期间暂缓**展示**某次规则变化，但不能更改规则结果。一次卡牌移动只由一个动效事务负责。每个可见移动必须明确选择“飞行”“翻面/揭示”或“有原因的直接更新”，不允许因找不到来源、目标或时长配置而悄悄跳变，随后再补飞。

本次范围是棋盘上玩家 Deck、Hand、Discard、Played、Swap、Develop、Breach 与 Supply、Trinket、Nemesis 专属牌堆之间的**可见卡牌转移**，以及 Conjure 一类临时展示卡牌。隐藏牌堆内部的洗牌和排序仍由引擎处理，不强制把每次内部重排都表现为卡牌飞行。现有 Nemesis 抽牌翻面、伤害反馈、Turn Order token 和 Breach 开合是独立效果；它们需要与卡牌事务正确等待和取消，但不在首轮迁移中重写。

### 当前架构中需要替换的部分

- `aeons-end-ui/src/game/useGame.ts` 同时维护 `handDiscardPresentation`、Deck/Discard 显示覆盖、待飞行手牌、多个快照和队列；有些展示覆盖只在 `pendingEffect` 路径建立，Nemesis To Discard 使用另一条 `pendingNemesisDiscard` 路径。
- `aeons-end-ui/src/game/card-flight.ts` 的 `resolveCardZoneTransfers`、`resolveCardZoneMotion` 等依靠前后数组数量或 DOM 增减推断移动。同名副本、临时展示和多个动作连在一起时，推断缺少唯一归属。
- 普通飞行与飞入玩家 Deck 的翻面飞行各自选择时长变量；区域 FLIP、飞行及目标显示的启动时机分散在组件和 `useGame.ts`。
- 现有 Woven Sky 浏览器测试验证手牌飞行与收拢，却没有验证三张牌落地前后 Discard 的顶牌和数量。

## 必须满足的行为契约

1. **规则与展示分离。** 引擎动作可同步完成；在下一次浏览器绘制前，UI 必须同步建立该动作的初始展示态。不能在第一次 `await`、`nextTick` 或其他动画结束后才覆盖已显示的最终规则状态。
2. **逐张提交。** 每张卡起飞时从来源的可见卡列移除，并让来源平滑收拢；到达目标时才在目标可见卡列或牌堆顶出现，目标牌堆计数才变化。若原玩家 Discard 数量为 `D`，Woven Sky 的三张手牌应使它依次显示 `D → D+1 → D+2 → D+3`，不能先 `D+3` 或到最后一次性 `D+3`。
3. **位置先准备，卡牌后出现。** 行式牌区可以在飞行开始时平滑腾出占位，但占位不是第二张卡。落地只揭示飞行的那一张，不再触发一次突兀重排。堆叠牌区在落地前保留旧顶牌和旧数量。
4. **唯一身份与唯一负责人。** 事务 ID、移动 ID、卡牌副本 ID 和来源/目标区域唯一标识贯穿规则事件、展示态和动画。一个移动 ID 只能起飞与落地各一次；同一实体不能同时作为静止卡牌和飞行副本出现。
5. **规则顺序决定依赖。** Swap 先让进入 Swap 的牌落定，再从更新后的位置捕获被换出的牌，飞向 Discard；批量弃牌按选择/规则顺序逐张处理。不同事务不得抢写同一个牌区的展示态。
6. **等待真实完成。** 后续规则步骤、决策弹窗、阶段推进和输入解锁要等待相关动画的 `finished`/统一完成信号，而非另写一个近似的 timeout。动画被取消或视图被销毁时也必须结清事务。
7. **收尾可校验。** 动画结束、取消、撤销、载入存档或切换不可见视角后，展示态必须与引擎一致；不得留下克隆、隐藏的真卡、占位或 inline transform。开发/测试环境对遗漏移动、重复领取移动、缺失区域锚点和最终状态不一致报错。

Control Bar 的 Hand 数字和白色手牌增长气泡继续遵守 `ui/ui-guide.md`：数字读取真实 `hand.length`，气泡只由真实手牌增加触发。牌堆表面卡牌与计数遵守上述落地时机。若以后希望 Control Bar 数字也随逐张飞行改变，应先修改正式 UI 规范，不能在此次重构中无意改变语义。

## 目标架构

### 1. 引擎动作的移动记录

在引擎通用移动原语处收集非持久化、类型化的 `CardMove` 事实，而非由 UI 比较卡牌数量猜测。每条记录至少包含事务/移动 ID、实体副本 ID、卡牌 ID、来源和目标的区域与持有者、来源和目标顺序、动作内序号、规则原因（如 `play`、`discard-cost`、`develop`、`swap`、`gain`）。创建、销毁、洗牌/重排与仅展示的揭示不伪装成普通区域移动；按各自的类型处理。移动记录不写入存档，也不包含像素坐标、CSS 时长或 Vue 元素。

玩家 Deck 已有实例 ID，部分 Nemesis 和专属牌堆也已有实例追踪；实施时须补足 Hand、Discard、Played、Swap、共享 Develop 等可见区域的副本身份，并使卡牌经过这些区域时保留同一个 ID。旧存档沿用当前补建实例的思路迁移。以动作前后的实例序列核对移动记录；差值检查只负责发现遗漏，不再负责生成动画。

### 2. 单一展示态与事务协调器

在 `aeons-end-ui/src/game/` 建立独立于规则状态的卡牌展示投影与动效协调器。调用引擎动作的统一入口顺序为：捕获当前展示与来源位置 → 同步执行引擎动作并取得移动记录 → **在首次 `await` 前**安装初始展示投影 → 更新 Vue → 按依赖调度飞行、行式区域 FLIP 和逐张落地 → 核对投影与 `GameState` → 释放输入与推进流程。

投影维护每个区域当前可见副本、牌堆顶牌/数量、占位及飞行中副本。Hand、Played、Swap、Develop 等行式区域从投影渲染；Deck、Discard 等牌堆表面从投影渲染。组件只负责布局和交互，不根据 DOM 差值认领移动。手牌与其他区域的 FLIP 可以继续由各自组件执行，但都由投影变化触发，并向协调器返回完成信号；同一行不再同时接受另一套 reflow 动画。

跨决策的打牌事务保持打开：需要执行完效果才离开手牌的 Gem/Relic 在展示态中继续留在 Hand；决策结束后根据真实结果释放其移动。Ctrl+Z 取消当前动效、恢复引擎快照和展示投影，不能先把卡牌显示在 Played。存档只保存规则状态；中途恢复时清理动画并直接从已保存的规则状态重建展示态，不尝试恢复半途飞行。

### 3. 区域注册表与统一渲染/计时

每种牌区注册稳定区域 ID、归属、当前可见性、来源卡/堆锚点、目标锚点、行式占位和重排接口。Supply 与 Nemesis 专属牌堆可以提供堆锚点；手牌与开放牌区提供实体卡锚点；隐藏或切换视角的区域须有明确退化策略。缺少可见锚点时，开发/测试环境失败并输出事务诊断；生产环境结清事务并直接同步最终展示态，**不得稍后再补播同一移动**。

建立穷尽的、带类型的 `MotionIntent → CSS token / easing / 翻面 / 布局策略` 映射。实际时长仍由 `styles/tokens.css` 提供，UI Gallery 可覆盖 token；普通飞行和 Deck 翻面飞行都必须使用同一个配置解析器与完成信号，不再各自挑变量或使用不同默认值。飞行渲染器统一处理卡牌宽高比、位置、层级和翻面；以统一缩放保持 `--card-aspect-ratio`，避免 Swap 小卡飞向大 Discard 时被非等比压扁。

## 回归矩阵与验收方法

至少覆盖以下路径和压力条件，而不只是检查动画结束后的最终游戏状态：

| 路径 | 代表场景 | 必查中间状态 |
| --- | --- | --- |
| Hand → Discard / Deck | Woven Sky 三张代价、普通批量弃牌、放到自己或盟友牌库顶 | 每张起飞时手牌平滑收拢；到达前目标顶牌/数量不变；逐张落地计数；同名牌身份正确。 |
| Hand → Played / Swap | 带决策的 Gem/Relic、Play All Gems、Swap | 决策未结束时仍显示在手牌；仅一次飞行；目标区域平滑让位；撤销返回手牌。 |
| Swap → Discard | 一张牌进入 Swap 并换出原有牌 | 第二张必须等第一张落地才起飞；Discard 到达前不预显；尺寸不被压扁。 |
| Supply → Develop → Discard | 商店 Develop、再次 Develop | 行式区域在飞行过程中平滑占位/收拢，落地不闪烁。 |
| 其他来源 → 玩家区域 | Supply 购买/获得、Crooked Mask 专属牌堆、Breach、Conjure Skip | 来源与目标归属正确；临时展示不误增真实 Hand 数字或气泡；隐藏来源有明确策略。 |

对上述路径再组合：一张/多张、同名副本、不同玩家、手牌溢出滚动、1440×900 与 1920×1080、可选 Skip、连续动作、动画期间撤销或视角切换、存档恢复、`prefers-reduced-motion`。单元测试用可控时钟验证事务投影、依赖和“移动只提交一次”；引擎测试验证移动事实和副本身份；Playwright 按帧采样可见数量、顶牌、卡面位置、重排幅度、飞行副本数、实际 `Animation.effect.getTiming().duration` 与宽高比。特别检查首帧、中途和每次落地，不能只断言最终状态或截图。Gallery 提供可重复播放和打断的样例，最后在目标桌面尺寸人工检查观感。

完整检查使用仓库既有命令：`aeons-end-engine` 中 `npm test`，`aeons-end-ui` 中 `npx vue-tsc --noEmit`、`npm run build`、`npm run test:e2e`、`npm run test:ui-gallery`。若任何路径缺少可见锚点、遗漏移动记录或回归仍显示早到/重复飞行，该批次不能标记完成。

## 委托实施时的执行协议

本节用于把上述计划交给另一名实现者或编码模型。**不要用一条“完成全部重构”的指令启动工作。** 只交付一个批次；审查其代码、测试和路线登记后，才开始下一个批次。批次 0 是必经步骤：当前移动入口分散，而且工作树可能已有未提交改动，直接按设想批量替换容易漏路径或覆盖现有工作。

每批开始前，先阅读根目录 `AGENTS.md`、`README.md`、`dev-guide.md`、`ui/ui-guide.md` 和本计划，检查 `git status --short`，保留已有工作树改动。只查当前批次相关的引擎源文件、组件、测试和必要的卡牌资料；以当前代码为准，不把计划中的候选文件名或旧交接快照当成事实。批次 0 可以增加复现测试与开发诊断，但不能顺手改动画逻辑或游戏规则。批次 1 先交付移动事件接口及规则移动点清单，明确旧存档兼容方式，再铺开代码；不得在未盘点直接写数组的路径时宣称“所有移动已被记录”。

### 在编码前冻结的接口决定

实现者须在批次 0 的报告中写出以下决定，作为后续批次的共同接口；如果当前代码使某项不可行，说明证据与替代方案后先停在该批次，不自行改变产品预期：

1. `CardMove`/创建/销毁/重排事件的类型、实体副本 ID 取得方式、动作序号及来源/目标区域 ID；事件是动作的临时输出，不进入存档，也不携带 UI 坐标或动效时长。
2. `useGame.ts` 的哪些公开行动入口共享一个展示事务；哪些自动效果需要独立事务；跨 `pendingDecision` 的打牌动作如何保留同一来源展示、如何确定最终释放时点。引擎可以继续先完成规则变化，事务展示不能因此提前移走待决策的 Gem/Relic。
3. 各类动作的旧动效所有者与新动效所有者，精确到完整动作链。Swap 的两次移动、同一决策产生的多张弃牌不能分给彼此争用展示态的两套实现。
4. 旧存档缺失实例 ID 时的补建和持久化规则，以及撤销、载入、视角切换、动画取消时的唯一清理入口。
5. 每个 `MotionIntent` 对应的 CSS token、翻面、行式占位和缺失锚点处理；已知 intent 不得默默落入 `standard` 时长。普通飞行与飞向 Deck 的翻面飞行使用同一个时长解析与等待方式。

### 不可曲解的时间线样例

| 场景 | 起飞前 | 飞行过程中 | 到达后 |
| --- | --- | --- | --- |
| Woven Sky 支付三张手牌 | 引擎可已有最终结果；玩家 Discard 表面仍为旧顶牌和 `D`，三张来源牌仍可见。 | 第 `i` 张起飞时才从 Hand 展示移除并平滑收拢；第 `i` 张未落地前 Discard 只显示前 `i-1` 张的结果。不存在目标静止副本与飞行副本并存。 | 三次落地分别显示 `D+1`、`D+2`、`D+3`；顶牌按真实规则的落牌顺序更新，最终与引擎完全一致。 |
| Swap | 被打出的牌仍处于正确来源；旧 Swap 卡仍在原位。 | 先为新卡平滑腾出 Swap 位置并飞入；新卡落定之前，旧 Swap 卡不能出现在 Discard，也不能开始第二段飞行。随后从**更新后的 Swap 位置**捕获旧卡，平滑收拢 Swap 并飞向 Discard。 | 旧卡落地时才更新 Discard 顶牌/计数；新卡稳定留在 Swap，不闪烁或重新飞行。 |
| Supply → Develop → Discard | 每一步独立按规则目标准备展示。 | Develop 在卡牌飞来时平滑让位，占位不绘制第二张卡；从 Develop 飞出时剩余卡平滑收拢。 | 到达只把占位替换成真卡或更新 Discard；不在落地时再突然重新排一次整行。 |
| 需决策的 Gem/Relic | 决策期间卡仍留在 Hand 的展示位置，不提前占 Played。 | 决策完成后只按真实去向飞行一次；其他 Gem 打出时不得让它在 Played 再跳变。 | Ctrl+Z 恢复该动作时回到 Hand 与正确决策状态，不短暂出现于 Played。 |
| Conjure Skip | 临时揭示牌可显示在 Hand 区域，但不属于真实 `hand`。 | Skip 后临时牌飞回 Deck；真实 Hand 数字和白色增长气泡始终不因该牌变化。 | Deck 表面数量在落地时更新；临时展示对象被清理。 |

上述时间线是浏览器可见行为，不要求引擎分帧改写规则。若真实落牌顺序与玩家选择顺序不同，以引擎事件中的实际顺序和最终牌堆顺序为准；先检查规则是否符合卡牌要求，不能仅在 UI 中重排动画来掩盖规则差异。

### 每批必须提交的证据

- 改动文件列表，以及本批处理的动作链/未迁移动作链清单；指出旧入口哪些已经删除或关闭。不能只声称“使用通用动画”。
- 每个关键场景至少一个**先失败、后通过**的回归断言；检查首帧、飞行中、每次落地和最终状态。计时用 `Animation.effect.getTiming()` 或统一完成信号核对，不以固定睡眠代替动画完成。
- 引擎状态、展示态和飞行中实体的核对结果；每个移动 ID 最多被认领一次。对多张同名牌检查副本 ID，不以卡牌定义 ID 充当实体 ID。
- 所运行命令的结果，明确区分本批新增失败与开始前已有失败。没有运行的测试和没有做的桌面目视检查必须如实列出。
- 如遇不确定的规则、旧存档迁移或无法测量的目标锚点，记录具体代码位置与待决问题，停在当前批次；不要用按卡牌 ID 的分支、静默 fallback、额外 timeout 或再次覆盖目标区域来临时消除现象。
